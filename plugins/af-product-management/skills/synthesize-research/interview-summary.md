# Single interview summary

The branch of `synthesize-research` for one customer interview transcript (pasted, uploaded, or rough notes). Several transcripts go through the main synthesis workflow instead, with cross-participant patterns.

## Steps

1. **Read the full transcript** before writing anything. With rough notes rather than a transcript, work from what is there and state the limits.
2. **Extract**: participant profile (role, segment, experience, context); jobs to be done; current workflow and solution; pain points, workarounds and time sinks; satisfaction signals; verbatim quotes with timestamps where available; surprises that contradict assumptions; reactions to any features or concepts shown; competitor products mentioned (capture them as competitive intelligence).
3. **Separate said from did.** Mark stated preferences apart from described behavior; behavior is the stronger evidence. Flag contradictions inside the interview (says one thing, describes doing another).
4. **Fill the template** below. Use "-" where information is missing; describe satisfaction qualitatively ("not satisfied") when no number was given. Write in plain language a primary school graduate could follow. Done when every heading is filled or marked "-", and every insight cites a quote or observation.

## Template

```
## Interview Summary

Participant: [anonymized: role, segment, experience]
Date: [date and time] | Duration: [if known] | Interviewer: [if known]
Background: [about the customer]

### Key insights
1. [Insight]: [supporting quote or observation]

### Jobs to be done
- Primary: When [situation], I want to [motivation], so I can [outcome]
- Related: [additional jobs]

### Current solution and workflow
[What they use today and how, step by step]

### What they like about the current solution
- [Job, desired outcome, importance, satisfaction]

### Problems with the current solution
| Pain point (job, desired outcome) | Importance | Satisfaction | Severity | Quote |
|---|---|---|---|---|

### Notable quotes
> "[quote]" on [topic]

### Assumptions validated / invalidated
| Assumption | Status | Evidence |
|---|---|---|

### Action items
- [Date, owner, action]
```

Save as markdown. Then offer to compare with other interview summaries, update the assumption list (`identify-assumptions`), or build personas across interviews (`user-personas`).
